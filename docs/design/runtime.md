# 运行控制

运行控制将任务、模型决策、工具执行和验证结果关联起来，负责版本隔离、预算和生命周期。它承载[整体架构](overview.md)中的内外环，开发状态见[运行底座计划](../plan/runtime.md)。

## 对象

| 对象 | 含义 |
|---|---|
| `Task` | 框架、模型、资源、目标、负载、行为契约和预算 |
| `Run` | 一次执行的状态、版本、来源和成本 |
| `Call` | 一次模型或工具尝试，包含输入输出、因果关系和耗时 |
| `Experiment` | 一个优化假设及候选版本、验证条件和结论 |
| `Proposal` | 一项改善 Sherpa 的外环提案及审核记录 |

环境调查的 `environment/proposal.json` 是目标任务的运行方案，与外环 `Proposal` 分开管理。

## 版本与数据

用户框架导入独立工作区并固定 commit；本地未提交源文件可以形成快照。模型目录独立引用。Sherpa 的代码与策略版本单独记录，使执行条件可追溯。

Run 保存状态快照和追加式事件；Call 保存原始响应、解析结果及输入输出哈希。运行数据位于项目与用户输入目录之外，文件内容作为证据处理。

## 执行与恢复

执行采用串行控制循环，每次行动前检查预算。取消、超时和异常均进入收尾，回收本次启动的进程组；清理失败阻止继续执行。

环境续跑创建关联的新 Run。恢复过程核对历史产物、复查文件证据、更新机器状态，并将未提交结果恢复为草案。新段使用追加预算，累计成本按来源链去重。

## 预算与结论

时间、调用次数、模型费用和资源分别计量。未知费用显式保留；资源阈值记录作用范围和触发原因。具体阈值属于执行配置，不属于架构常量。

Run 的结束状态描述过程；环境就绪、行为通过和性能改善分别由对应验证产物证明。
