# Agent

Agent 层为业务流程提供统一的模型调用接口。角色决定职责，backend 决定接入方式；两者独立配置。开发状态见[Agent 计划](../plan/agent.md)。

## 角色与控制权

| 角色 | 输入 | 输出 |
|---|---|---|
| 日常决策 | 任务约束、工具能力、事实、历史尝试和剩余预算 | 一个下一步动作 |
| 限定专家 | 明确的问题、介入原因、证据和完成条件 | 有边界的结果或建议 |

日常模型掌握控制权。专家完成后交回结果，工具由 Sherpa 调用。事实、专家意见和待验证假设分别呈现。

## 调用链

`业务请求 → Router → 角色候选池 → Backend → 响应校验 → Call 记录`

- 请求声明角色、任务、上下文和输出契约。
- Router 串行尝试同角色候选；限流、不可用、认证、网络或候选超时触发切换。
- 格式或字段错误返回原流程修正。角色池耗尽停止该请求，不自动升级角色。
- Backend 封装提供方协议和进程监管；更换提供方不改变环境或优化逻辑。

每次尝试记录请求模型、提供方报告模型、原始响应、token、费用与错误。记录缺失的字段保持未知，不推断为零或已核验。

## 上下文与输出

工具将原始结果加工为有来源的事实和可下钻片段。模型选择证据和动作，程序填写固定身份、复制原文并校验结果，减少机械抄写。

输出校验检查结构和已知约束；兼容性及优化收益由执行验证证明。专家介入与候选切换都消耗预算。
