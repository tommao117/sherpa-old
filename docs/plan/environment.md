离线检查入口：`python3 -B -m sherpa.cli env check-contract task.json --action action.json --approval approval.json`。只读取显式 JSON 和文件元数据，打印报告，不创建 Store/Run 或执行动作。退出码：0 为离线有效、2 为契约不合格、1 为输入读取/解析失败；未提供 approval 会返回缺失诊断与 Task 哈希，不生成授权。

E1 通过只说明声明与元数据符合要求；真实授权、输入内容和设备在 E3 前复核。E2 入口为 `python3 -B -m sherpa.cli env test-executor --scenario normal`，只执行固定夹具，结果与日志按 Run/Call 保存；不接受用户程序、模型路径或 GPU 参数。

E2 的 30 项测试覆盖固定管线、构建关联、冻结输入、验证失败/证据不足、日志限额、累计磁盘、局部/全局超时、取消、父死亡、清理异常和预算不可复位。该阶段全量 266 项通过，约 97 秒。一次中间专项运行曾有未复现失败，补充了完整错误输出并修复磁盘轮询的临时文件竞态，后续专项及全量通过；不将其当成稳定性统计。

## E3 离线交付与剩余工作

- `llama_completion.py` 根据显式 Task 和路径生成 configure/build/run_once 命令草案，未接入执行入口；`plan-completion` 不创建 Run。日志解析只提取设备、卸载层数和实际 eval 计数，不给运行通过结论。
- 固定源码中 `llama-cli` 依赖 server 且启动本地 HTTP；单次无服务请求采用同框架的 `llama-completion`。选项使用 `--load-mode none`，不套用旧版 `--no-mmap`。
- 18 项新增离线测试覆盖源码对应参数、Q8 选择、环境隔离声明、路径冲突、输入异常及日志缺失/重复/截断；全量 284 项通过，约 99 秒。日志样例为源码格式合成，不是 GPU 证据。
- `execution_records.py` 已实现只读 prepare/configure/build 绑定，拒绝模拟记录、跨 Run 产物、命令或契约不一致、未清理进程记录及二进制篡改；20 项新测试采用手工临时记录，不产生真实构建证据。最新全量 304 项通过，约 100 秒。
- 后续接执行授权与当前环境检查：系统级 `/etc/llama.cpp/config.ini`、源码状态、真实工具路径、模型身份及单 UUID 到 CUDA0 的映射。记录核验暂为内部 API，真实执行器尚未写入对应构建记录；offline 选项不是网络沙箱。
- 显卡空闲且执行范围确认后，再连接真实执行器做一次冒烟。暂不建立性能基线，不把离线适配通过算作 E3 完成。

## 最小验收集

- **契约**：分片及配套文件可联合选择；多个互斥备选、越界路径、身份变化和缺必填项均拒绝，旧报告不自动授权。
- **诊断**：同时缺文件选择和请求样本时一次返回两项问题；依赖它们的检查标为跳过；合法的只读探测仍可进行。
- **执行**：实际命令由适配器生成并校验；每次调用独立留痕。非零退出、产物缺失和源码被改不能通过。
- **生命周期**：运行中取消、超时、父进程退出和额度耗尽均清理自有后代；不影响无关进程，不自动重放历史动作。
- **结果**：成功退出不等于行为通过；某检查缺少所需参考或证据则为 `inconclusive`，已证明违反该项要求为 `fail`。契约必需项全部通过才整体 `pass`，冒烟通过不能覆盖行为未验证或失败。
- **复现**：同一输入与构建/请求配置可再次运行，变更产物或契约后旧验证结果失效。

接入复用 `Task`、`Calls.new/finish`、框架版本绑定及现有进程监管，不将模拟 `Calls.tool` 改称真实执行。构建与请求适配器接入环境流程，验证器独立于模型输出。

两次草案恢复分别限 180 秒/12 调用/6 轮和 120 秒/8 调用/5 轮；最后一次修正输出为 444 token。它证明局部修正可行，不代表从零调查稳定提效。样本少、预算或动态状态不同的运行不作统计结论；提供方报告费用为 0，不等于账单免费。

上述调查阶段的离线记录为 207 项通过，其中草案测试 20 项。E1 后为 236 项、E2 后为 266 项，E3 离线适配后为 284 项。

## 未解决问题与约定

- 历史方案混列 Q4_K_M 和 Q8_0。当前已明确选择 Q8_0，不修改旧报告；新执行契约仍需记录经授权确认的内容身份。
- GGUF 架构、概率接口、CUDA 工具链和 GPU 执行均未验证。搜索不到架构名称不构成不支持的结论。
- 只读工具不加载权重、不执行包内脚本；安装或模型执行需要独立能力与授权范围。
- 旧单目录 `env plan` 是声明扫描工具，不替代双输入调查；依赖 profile 分开解析，未解析内容保留待审。
- 原始 Call 不修改。`report-draft.json` 保存完整派生候选及原始响应/基底哈希；修正后整份报告重验。失效文件证据和机器状态不能随草案复活。
- 可见片段与 pin 只是任务内状态。方案中的命令是待验证内容，不由文档或模型输出自动授权执行。

实现入口：`sherpa/runtime/explore.py`、`decision_support.py`、`evidence_windows.py`、`report_drafts.py`、`sherpa/platform/exploration.py`。运行恢复见[运行底座计划](runtime.md)。
