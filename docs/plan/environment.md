离线检查入口：`python3 -B -m sherpa.cli env check-contract task.json --action action.json --approval approval.json`。只读取显式 JSON 和文件元数据，打印报告，不创建 Store/Run 或执行动作。退出码：0 为离线有效、2 为契约不合格、1 为输入读取/解析失败；未提供 approval 会返回缺失诊断与 Task 哈希，不生成授权。

E1 通过只说明声明与元数据符合要求；真实授权、输入内容和设备在 E3 前复核。E2 入口为 `python3 -B -m sherpa.cli env test-executor --scenario normal`，只执行固定夹具，结果与日志按 Run/Call 保存；不接受用户程序、模型路径或 GPU 参数。

E2 的 30 项测试覆盖固定管线、构建关联、冻结输入、验证失败/证据不足、日志限额、累计磁盘、局部/全局超时、取消、父死亡、清理异常和预算不可复位。该阶段全量 266 项通过，约 97 秒。一次中间专项运行曾有未复现失败，补充了完整错误输出并修复磁盘轮询的临时文件竞态，后续专项及全量通过；不将其当成稳定性统计。

## E3 试测范围与交接

- **入口已接通**：`completion-template` → `stage-completion --allow-input-preparation` → `run-completion --approve-ticket-hash`。操作步骤见 [README](../../README.md)，状态、取消与日志复用现有 Run/Call。
- **范围固定**：本地已固定的 llama.cpp、单个 GGUF、单张 GPU、单次 `llama-completion` 请求；不启动服务，不调用决策模型，不安装或下载依赖。模板不是资源授权。
- **已验证**：18 项命令/日志测试、20 项记录核验、27 项运行入口及监管测试；全量 331 项通过，约 119 秒。集成测试实际运行临时假编译器和假 GPU 查询，并验证小型 Git 对象复制；没有真实 CUDA/JEV 证据。
- **准入与停止**：票据绑定 Task、模型/工具/控制代码身份；系统配置、源代码变化、忙卡或 GPU 观测不明均阻塞。配置、构建、推理异常返回记录，不重放或追加预算。
- **已修边界**：禁用 Git fsmonitor/hooks，拒绝含 BOM 的外部配置/过滤器；构建后重新核对模型；嵌套 GPU 查询不暂停主任务 deadline/RSS；磁盘扫描节流，避免大权重哈希触发逐块全树扫描。
- **下一步**：显卡空闲并确认输入、预算与权限后开始真实试测，围绕实际阻塞迭代。先验收 GPU 冒烟，再接决策模型控制、JEV 行为与性能基线；不把替身集成通过计为全局跑通。

## 最小验收集

- **契约**：分片及配套文件可联合选择；多个互斥备选、越界路径、身份变化和缺必填项均拒绝，旧报告不自动授权。
- **诊断**：同时缺文件选择和请求样本时一次返回两项问题；依赖它们的检查标为跳过；合法的只读探测仍可进行。
- **执行**：实际命令由适配器生成并校验；每次调用独立留痕。非零退出、产物缺失和源码被改不能通过。
- **生命周期**：运行中取消、超时、父进程退出和额度耗尽均清理自有后代；不影响无关进程，不自动重放历史动作。
- **结果**：成功退出不等于行为通过；某检查缺少所需参考或证据则为 `inconclusive`，已证明违反该项要求为 `fail`。契约必需项全部通过才整体 `pass`，冒烟通过不能覆盖行为未验证或失败。
- **复现**：同一输入与构建/请求配置可再次运行，变更产物或契约后旧验证结果失效。

接入复用 `Task`、`Calls.new/finish`、框架版本绑定及现有进程监管，不将模拟 `Calls.tool` 改称真实执行。构建与请求适配器接入环境流程，验证器独立于模型输出。

上述调查阶段的离线记录为 207 项通过，其中草案测试 20 项。E1 后为 236 项、E2 后为 266 项，E3 离线适配后为 284 项。
