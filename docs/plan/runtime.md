# 运行底座开发计划

更新：2026-11-13｜设计：[运行控制](../design/runtime.md)

## 已具备

- `Task/Run/Call/Experiment/Proposal` 的结构或存储接口，事件、快照、因果关系和成本记录。
- 串行模拟循环、独立代码快照、失败/取消/超时收尾，以及自有进程组清理。
- 用户指定 HTTPS Git 或本地框架导入；真实固定 commit 准备与复制续跑已验证。
- 环境证据续跑新建 Run，保留原记录；文件重验、机器刷新、窗口与草案恢复。

## 后续任务

| 任务 | 验收 |
|---|---|
| 接入环境执行器 | 构建、启动和请求均关联 Call；失败与取消有明确终态和清理证据 |
| 执行工件复现 | 目标版本、模型输入、环境与启动配置可重建，并区分任务版本与 Sherpa 版本 |
| 扩展恢复场景 | 明确中断后可恢复的执行步骤；未收敛的进程不被当成安全检查点 |

## 实现约定

代码入口：`sherpa/runtime/store.py`、`calls.py`、`workspace.py`、`framework.py`、`continuation.py`。

- 数据默认在仓库外的 `../sherpa-data/`；不得嵌入目标或模型目录。
- 远程首次浅获取，固定 commit；本地快照包含合格的未提交源文件。续跑复制 Git 对象和浅历史边界，不重拉 HEAD、不硬链接、不复制 hooks 或外部对象引用。
- 框架工作区默认 512 MiB；本地源快照使用一半预算预留 Git 开销。Git 操作上限为 120 秒、60 CPU 秒、512 MiB 虚拟内存，pack/index/checkout 单线程。阈值与退出结果写入调用日志。
- 子模块、LFS 获取及交互认证尚未接入。仅提供受控工具，不构成任意代码沙箱。
- 终态 Run 不复活；清理失败或遗留运行中调用的恢复需单独处理。成本按来源链去重，未知费用保留未知。

模拟入口与测试：`sherpa/runtime/simulation.py`、`tests/test_runtime.py`。真实环境执行测试随执行器接入补齐。
