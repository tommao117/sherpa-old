# 反思与知识开发计划

更新：2026-11-13｜关系：[整体设计](../design/overview.md)中的外环

## 目标与状态

外环从任务 trace 找出通用能力缺口，验证并审核工具、知识或流程改进，使后续任务更可靠、成本更低。

已具备反思 Run、改进 Proposal 和审核状态的存储接口。事实组织、资料定位与草案修正由开发会话人工监督实施；自动反思、应用变更、发布和知识管理尚未接通。

## 任务

| 任务 | 验收 |
|---|---|
| 提炼反思输入 | 成功与失败记录都可追溯，区分模型、工具、上下文和任务约束问题 |
| 生成限定改进提案 | 明确问题、证据、适用范围、改动与验证方法 |
| 接入人审与实施 | 审核身份、授权和执行分开记录；批准不直接等于发布 |
| 复测与版本采用 | 有代表性的多任务比较，保留无效改进与回退记录 |

## 开发约定

- 可以与内环开发并行，但每项改进必须对应可观察的主线阻塞或可靠性问题。
- 优先沉淀工具和清晰接口，知识记录适用条件与证据；单个模型的操作答案不能变成全局规则。
- 内环期间固定 Sherpa 版本，外环验证后的变更用于后续运行。
- 任务内证据窗口、专家建议和环境运行方案不自动进入正式知识库。

自动化范围和审核机制仍需设计，当前以人工监督的有限改进批次推进。
