# 优化与评测开发计划

更新：2026-11-13｜依赖：[环境准备](environment.md)完成真实请求验证

## 目标

建立可信行为参照和性能基线，再验证目标代码修改是否产生有效收益。整体关系见[整体设计](../design/overview.md)。

## 状态与任务

模拟链已有基线、候选、行为检查、测量、最好版本和失败收尾。真实模型尚无对应基线或优化实验。

| 顺序 | 任务 | 验收 |
|---|---|---|
| 1 | 定义行为契约与测试集 | 明确输出语义、容差、样本范围及失败判定 |
| 2 | 建立性能基线 | 固定模型、负载、设备、环境和测量方法，可重复观测 |
| 3 | 接入候选代码实验 | 修改位于隔离版本，实验记录假设、差异、调用与成本 |
| 4 | 验证并交付最好结果 | 行为通过后比较性能；无收益或证据不足时保留已有有效版本 |

## 开发约定

- 模型、量化、输入长度、设备和行为标准是比较条件，变化需要显式记录与确认。
- 吞吐、延迟及资源指标按任务选择，阈值和重复测量要求在真实实验前确定。
- 显存增长、成功加载和模型自述不能替代行为与性能证据。
- `sherpa/runtime/simulation.py` 的合成指标仅用于验证控制流程，不计入真实收益。

详细执行器和评测接口在前置运行契约明确后设计，避免围绕单个案例提前固化。
